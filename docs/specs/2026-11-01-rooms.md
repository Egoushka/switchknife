# Rooms, the log under every hand: spec

Design and reasons: `docs/adr/0007-rooms-log.md`. Status: proposed. Depends on `Switchknife.Journal.Postgres` 0.1 (`step_events`), `Switchknife.McpGuard`, and, for the projections only, `Switchknife.Facts` 0.1.0, K3 (`IdeaStore`, `KnowledgeApprovals`) and K4 (`RoundIngest`, switchknife#51, not merged).

## Goal

An agent keeps no memory of its own; it is a hand. What happened lives in a **room**: one ordered, append-only, hash-chained log of events that every participant (the owner, Claude Code sessions, chargehand runs, services) writes into. Any agent rebuilds its picture of a room at any point T with one read, `room_brief(room, as_of)`, so a stopped or crashed task resumes in a fresh session without redoing work or re-asking the owner. `HANDOFF.md` becomes a query instead of a ritual.

Knowledge rewinds; the world does not. A brief at T is a read and costs nothing. A sent message, a merged PR or a deleted row cannot be undone, only compensated, so every side effect records its **undo kind** (`revert`, `compensate`, `none`), and a brief at T lists which effects after T are still in force and how each can be reversed.

The log is the one raw layer under the existing memories, not a sixth one: Facts, the idea board (K3), research rounds (K4) and Hindsight directives become **projections**, derived from the log and rebuilt by replaying it.

## What already exists, and what rooms add

| Need | Already there | Evidence | Rooms add |
|---|---|---|---|
| Append-only events per flow, replayable | `step_events` (`seq`, `flow`, `kind`, `at`, `payload json`), `AppendEventAsync`, `ReadEventsAsync(flow, after)` | `src/Switchknife.Journal.Postgres/Migrations/0001_steps.sql`, `PgStepStore.cs` | Per-room sequence without gaps, actor, occurrence time, undo kind, refs, hash chain, idempotency key, forks |
| Events that cannot be lost | none: `ForgetAsync(flow)` deletes a flow's events, and chargehand's `TaskJournal` calls it for a finished batch | `IStepStore.ForgetAsync`, chargehand `TaskJournal.cs` | A room flow refuses `ForgetAsync`; only an explicit purge removes content, and it leaves the chain verifiable |
| Knowledge as of a date | Facts is bi-temporal (`AsOfAsync(validAt, knownAt)`) | `src/Switchknife.Facts/README.md` | The Facts projection answers "as of event N" with `knownAt` = that event's recorded time |
| Raw record of every session | Claude Code transcripts: one JSON line per message with `uuid`, `parentUuid`, `sessionId`, `timestamp`, `cwd`, `gitBranch`, `isSidechain`, `permissionDecision`, `toolUseResult` | read from local transcripts on 2026-11-01 | A transcript adapter and a tailer that copy them into rooms |
| Exact, cited reads for agents | K4's brief: exact filters, count cap with `truncated`, never a score | switchknife#51, "Brief" | The same rules over a room |
| Tool definitions with an employer fence | `KnowledgeTool(Name, Description, InputSchema, Private, Handler)` | `src/Switchknife.Knowledge/Tools/KnowledgeTool.cs` | `room_brief` and `room_append` in the same shape |
| Guarded MCP endpoint | `RequireMcpGuard` (no `Origin`, fixed-time bearer) | `src/Switchknife.McpGuard/README.md` | Nothing; the host maps the tools behind it |

## Out of scope

- Semantic search. ADR 0006 stopped agent-facing retrieval (recall@10 0.199 against 0.32). Every read here filters by room, sequence, time, kind, actor or ref, exactly.
- Calling a model. The kit stores, chains, filters and counts; summaries are the reading agent's job.
- Undoing anything in the world. The log records the undo kind and the ref of the action that would reverse an effect; running that action is a host's job, through the approvals shell.
- Capturing anything that a transcript, a journal or a host does not already emit. Slice 1 ingests; it does not instrument.
- The time-travel review page (scrub a room, fork from a point). It is a front end and waits for the check below.

## Where this differs from the design note, and why

| Design note says | Spec does | Reason |
|---|---|---|
| "Chargehand runs already write journal events, so they join without code" | A chargehand adapter copies a run's events into its room (slice 3) | Chargehand's journal is a SQLite file in its state directory (`DrivenJournal` calls `StepJournal.OpenAsync(path)`), not the shared database, and `TaskJournal` forgets a finished batch's flow. Without a copy the events are neither shared nor permanent |
| `room_open(room, as_of?)` returns the brief | `room_brief(room, as_of, filters)` is a pure read; a participant joins by its first append (`joined`) | A read that writes cannot be replayed at T, and a brief requested for evaluation must not change the room |
| Event `{room, seq, ts, actor, kind, body, refs, undo, prev_hash}` | Adds `hash`, `body_hash`, `source_id`, `recorded_at`; the chain covers `body_hash`, not the body | A privacy purge or a retention prune removes a body and must leave the chain verifiable. `source_id` makes a re-ingest of the same line a no-op |
| Kinds: said, tool_call, tool_result, decision, observation, side_effect, snapshot | Adds `joined`, `forked`, `linked` | Participants, forks and links to other flows must be events, or a brief at T cannot rebuild them |
| "A Claude Code hook (or the `ws watch` indexer)" copies each event | A tailer outside the tool path | A hook runs inside every tool call and would spend the 100 ms budget; a tailer spends none of it, and the transcript file is its own queue while the database is unreachable |
| Ingest "under a room key" | Room = `task/<repo>/<branch>` when the line has a non-default branch, else `session/<session id>` | The workspace rule is one task = one branch = one PR, so a task continued in a new session lands in the same room; the re-ask check depends on it |
| HANDOFF.md becomes a query | HANDOFF.md stays until the check passes | The stop condition compares the brief against it |

## Contract

### Room

A room is a Journal flow whose key starts with one of these prefixes:

| Prefix | Example | Created by |
|---|---|---|
| `task/` | `task/switchknife/docs/rooms-spec` | The transcript adapter, from the line's repository and branch |
| `session/` | `session/0f9c2e4a-…` | The transcript adapter, for a line on a default branch, a detached head or outside a repository |
| `topic/` | `topic/phone-shell` | A host, for research rounds (K4) |
| `run/` | `run/<chargehand run id>` | The chargehand adapter, when the run names no room |
| `fork/` | `fork/<uuid v7>` | `ForkAsync` |
| `me/` | `me/body`, `me/attention`, `me/talk`, `me/work`, `me` | A stream adapter per source (slice SM); `me` holds every `correction` |

A `rooms` row holds the key, the parent room and sequence for a fork, the creation time and the room's sharing mode. A room's key never changes.

### Event

Stored in `step_events`, extended by migration `0002_rooms.sql` with nullable columns, so step flows written before it read and write as they do today:

| Field | Column | Meaning |
|---|---|---|
| room | `flow` (existing) | The room key |
| seq | `room_seq bigint` | 1, 2, 3, … inside the room, no gaps; assigned under the room's lock |
| recorded_at | `at` (existing) | The store's clock when the event was appended |
| ts | `ts timestamptz` | When it happened at the source (the transcript line's `timestamp`); for a live append, the store's clock |
| actor | `actor text` | `owner`, `user:<session>` (a session's user turn: the owner or the session that started it, which a transcript does not tell apart), `agent:<session>`, `subagent:<session>/<agent>`, `run:<id>`, `service:<name>` |
| kind | `kind` (existing) | One of the closed set below; any other value is refused |
| body | `payload` (existing, `json`) | The event's JSON after the fences; JSON `null` when purged or when the room's mode is `metadata` |
| refs | `refs text[]` | Typed pointers: `git:<repo>@<sha>`, `pr:<owner>/<repo>#<n>`, `room:<key>@<seq>`, `journal:<flow>#<seq>`, `cc:<session>/<uuid>`, `facts:<namespace>/<id>`, `approvals:<item>` |
| undo | `undo smallint` | Required on `side_effect`, refused on every other kind: `revert`, `compensate`, `none` |
| source_id | `source_id text` | Idempotency key, unique per room: `cc:<uuid>/<block index>` for a transcript block, `journal:<flow>#<seq>` for a copied event |
| body_hash | `body_hash bytea` | SHA-256 of the body's UTF-8 bytes as stored (after redaction); kept when the body is purged |
| prev_hash | `prev_hash bytea` | The previous event's `hash`; 32 zero bytes for seq 1 of a room that is not a fork |
| hash | `hash bytea` | SHA-256 over the canonical envelope (below) |
| purged_at | `purged_at timestamptz` | Set when the body was removed; the row and its hash stay |

**Kinds.** `said` (text a participant wrote), `tool_call`, `tool_result` (with `is_error`), `decision` (a permission answer, an `AskUserQuestion` answer, an approvals tap), `observation` (a deploy, an alert, a sense reading), `side_effect` (with `undo`), `snapshot` (a pointer to a git SHA, a GitOps tag or a backup id), `joined` (a participant's first event in the room), `forked` (first event of a fork), `linked` (another flow or room now belongs to this one), `correction` (the owner says an answer or a self-page line was wrong; body `{text}`, ref to what it corrects).

**Undo kinds.** `revert`: an action exists that restores the earlier state and leaves nothing behind (a revert commit of an unmerged branch, a deleted branch pushed again). `compensate`: an action cancels the effect, but the effect was visible (closing a PR, reverting a merged PR, deleting a posted comment, a refund). `none`: nothing cancels it (a sent message read by a person, a force-push over unrecorded history, a deleted row with no backup). A `side_effect` whose undo is `revert` or `compensate` carries the ref the reversing action needs (the PR, the remote branch, the comment id). A later event that reverses it carries `room:<key>@<seq>` of the effect, which is how the brief knows an effect is no longer in force.

**Canonical envelope.** `hash = SHA-256("rooms/v1" ‖ u64 seq ‖ s room ‖ s ts ‖ s actor ‖ s kind ‖ s undo ‖ s refs ‖ body_hash ‖ prev_hash)`, where `s x` is a 4-byte big-endian length then UTF-8 bytes, `ts` is RFC 3339 UTC to the microsecond (as PostgreSQL keeps it), `undo` is the empty string when absent, and `refs` is the refs sorted ordinally and joined by `\n`. Lengths make the encoding unambiguous; sorting makes it independent of the order refs were given.

**Append.** One transaction per batch: `pg_advisory_xact_lock` on the room key, read the room's last `room_seq` and `hash`, insert. Because the sequence is assigned under the lock and the lock is held to commit, a room's `room_seq` order is its commit order, so a reader that resumes after seq N never misses an event (the table's global identity `seq` gives no such promise across concurrent writers). A batch with a `source_id` already in the room skips that event and reports it as a duplicate.

**Verify.** `VerifyAsync(room, upTo)` recomputes every hash from seq 1 (through the parent's prefix for a fork) and returns the first seq whose stored hash differs, or none. A purged body does not change the result: the hash covers `body_hash`, which purge keeps.

**Purge.** `PurgeBodyAsync(room, seq, reason)` sets the body to JSON `null` and `purged_at`, and keeps every other column. `PurgeRoomAsync(room)` deletes a whole room (rows, `rooms` row, projection checkpoints); it is the only way to delete rows, and `ForgetAsync` on a room flow throws `InvalidOperationException`. Projections are told about both (see Projections).

### Fork and `as_of`

`ForkAsync(room, atSeq)` creates `fork/<uuid v7>` with parent `(room, atSeq)`. Its seq 1 is `forked` with refs `room:<parent>@<atSeq>` and `prev_hash` = the parent's hash at `atSeq`, so the fork's chain continues the parent's. Reading a fork reads the parent's events up to `atSeq`, then its own. Forking never edits the parent; that is how "reset to a point" works.

`as_of` takes either a sequence or a time:

- `as_of: {"seq": N}`: events with `room_seq ≤ N` (a prefix; the chain is verified up to N).
- `as_of: {"time": T}`: events with `ts ≤ T`. A task room interleaves sessions by ingest order, so this is a filter, not a prefix; the brief reports the highest seq it included and verifies the chain up to it.
- Absent: the whole room.

### Transcript adapter (slice 1)

A pure function from transcript lines to events; it opens no file and no connection. Per line:

| Transcript content | Event |
|---|---|
| `type: user`, text content, no `toolUseResult` | `said`, actor `user:<session>` |
| `type: assistant`, `text` block | `said`, actor `agent:<session>` (or `subagent:` when `isSidechain`) |
| `type: assistant`, `tool_use` block | `tool_call`, body `{name, input}`; refs `cc:<session>/<uuid>` |
| `type: user`, `tool_result` block | `tool_result`, body `{tool_use_id, is_error, content}`; ref to the call |
| `permissionDecision` on a line | `decision`, body `{tool_use_id, decision}` |
| `tool_result` of `AskUserQuestion` | `decision`, body `{questions, answers}` |
| `thinking` block | not ingested: model-internal, often signed or redacted, and the largest share of a transcript. If the check misses "why" questions, a variant with thinking is the first thing tried |
| `tool_use` matched by the side-effect rules below | `side_effect` with `undo`, in addition to the `tool_call` |
| `tool_result` of a `git commit` with a SHA in its output | `snapshot`, ref `git:<repo>@<sha>` |

Room routing: the host passes a resolver from `cwd` to a repository name (the folder before `.claude/worktrees/`, else the git top level's name) and the set of default branch names (`main`, `master`). A line with a repository and a `gitBranch` that is neither a default name nor `HEAD` goes to `task/<repo>/<branch>`; any other line goes to `session/<session id>`. A session that changes branch writes into each room in turn; each room gets a `joined` the first time.

Side-effect rules, a starting set widened only when a check run misses an effect: the first simple command of a `Bash` call, after the same unwrapping the workspace guard does (`sh -c`, `env`, `$(…)`):

| Command | Undo | Ref the undo needs |
|---|---|---|
| `git push` without `--force`/`--force-with-lease` | `revert` | `git:<remote>/<branch>@<sha>` |
| `git push` with force | `none` | the overwritten SHA when the output shows it |
| `gh pr create` | `compensate` (close it) | `pr:<owner>/<repo>#<n>` from the output |
| `gh pr merge` | `compensate` (revert PR) | the PR |
| `gh issue create`, `gh pr comment`, `gh issue comment`, `gh pr review` | `compensate` (close or delete) | the issue or comment |
| An MCP tool whose name the host lists as sending (chat posts, mail, notifications) | `none` | the tool call |

File edits (`Edit`, `Write`) are `tool_call`s with a path ref, not side effects: they stay in a worktree that git can restore, and a commit that keeps them is a `snapshot`.

### Fences (privacy)

Applied in this order to every event before it is written. A fence that cannot decide (a scanner that throws, a resolver that fails) refuses the event, and the tailer stops at that line: closed, not open.

1. **Employer fence.** The host configures employer roots (folders) and employer sources (MCP server names, memory banks), outside this repository. A line whose `cwd`, or any path in its tool input, lies under an employer root, or whose tool call names an employer source, **quarantines its session**: that line and every later line of the session are dropped, and the tailer records only a count (`fenced`, no content). Earlier lines passed the same check one by one and stay. A session whose first line is under an employer root writes nothing at all. This is the same work-session rule the workspace guard enforces on tool calls, applied to the log; employer sessions go only to the separate work memory (workspace decision D-48).
2. **Sharing mode** of the target room, the approvals shell's four modes applied to rooms. The host maps room prefixes to modes; the default is `redacted`.

   | Mode | What is written |
   |---|---|
   | `local-only` | Nothing; the room stays in the transcript on the machine that made it |
   | `metadata` | The envelope (kind, actor, times, refs, undo, hashes); body JSON `null`, `body_hash` of the redacted body |
   | `redacted` | The body with secrets and personal data (email, phone, card and IBAN numbers) masked |
   | `full` | The body with secrets masked |

3. **Secret scan**, never skipped in any mode that writes a body. `ISecretScanner` returns spans with a rule id; each span is replaced by `[secret:<rule>]` before `body_hash` is computed, so the stored hash never confirms a guessed secret. The kit ships `RegexSecretScanner` (source-generated `Regex`, AOT-safe) with rules ported from the workspace guard's masks; a parity fixture runs through both and must match.

`room_brief` and `room_append` are marked `Private`, so the host never serves them in the employer workspace (the K3 rule, I21). `room_append` refuses a room key the employer fence would refuse.

### Tools

Definitions in the `KnowledgeTool` shape (name, description, schema from `JsonTypeInfo`, `Private: true`, handler); the host registers them behind `RequireMcpGuard`. The caller's identity comes from the host (its token or session), never from the input.

**`room_brief`** — read-only.

```json
{
  "room": "task/switchknife/docs/rooms-spec",
  "as_of": { "seq": 412 },
  "kinds": ["decision", "side_effect"],
  "actors": ["owner"],
  "seq_from": 300,
  "ref": "pr:Egoushka/switchknife#52",
  "limit": 100
}
```

Only `room` is required. `as_of` is `{seq}` or `{time}`. `kinds`, `actors`, `seq_from` and `ref` narrow the event window; they never change the fixed sections. `limit` caps the event window (default 100, a starting value: the check reports tokens per brief and sets it).

Response, every section computed by an exact rule:

| Section | Rule |
|---|---|
| `room`, `as_of_seq`, `head_hash`, `verified` | The highest seq included, its hash, and whether `VerifyAsync` passed up to it. A broken chain returns code `chain_broken` with the first bad seq and no events |
| `parent` | For a fork: the parent room and seq |
| `participants` | Every `joined` up to T, with first and last seq per actor |
| `goal` | The room's first `said` by a `user:` or `owner` actor |
| `decisions` | Every `decision` up to T |
| `side_effects` | Every `side_effect` up to T with its undo kind, ref, and `in_force` (false when a later event up to T refs it as reversed) |
| `after_t` | For a fork or an `as_of` before the head: side effects in the parent or room **after** T that are still in force. Rewinding knowledge does not rewind them; this section says so in data |
| `snapshots` | The latest `snapshot` per repository up to T |
| `failures` | The last 10 `tool_result`s with `is_error` up to T (10 is a starting value, set by the check like `limit`) |
| `links` | Every `linked` up to T |
| `events` | The newest `limit` events up to T after the filters, oldest first; bodies as stored (purged ones as `null` with `purged: true`); `truncated` when more matched |
| `facts` | From the Facts projection (slice 4 on): live facts whose source is an event of this room, as known at T's `recorded_at` |

No section is ranked by a score; a cap cuts by count and says so.

**`room_append`** — writes one event.

```json
{
  "room": "task/switchknife/docs/rooms-spec",
  "kind": "side_effect",
  "body": { "what": "opened PR", "pr": 52 },
  "refs": ["pr:Egoushka/switchknife#52"],
  "undo": "compensate",
  "source_id": "hand:7f3c/step-4"
}
```

Returns `{seq, hash, duplicate, redacted}` (`redacted` = count of masked spans), or a refusal with a code and a field, never input text (K3 rule I6): `unknown_kind`, `undo_required`, `undo_not_allowed`, `undo_ref_missing` (`revert` or `compensate` with no ref), `fenced`, `mode_local_only`, `room_unknown_prefix`, `scanner_failed`. `ts` and `actor` are set by the host.

### Projections

`IRoomProjection { Name; Version; ApplyAsync(event, transaction); OnPurgedAsync(room, seq?); ResetAsync() }`. A runner reads every room's events in `room_seq` order from a checkpoint table `room_projection_checkpoints(name, version, room, last_seq)` and applies them in the projection's own transaction where it shares the database. A new `Version` or `ResetAsync` replays from seq 1. The rule every projection must meet: **rebuild equals incremental** (delete the projection, replay, compare).

| Projection | Reads | Writes | Rebuild |
|---|---|---|---|
| Facts | Events whose body carries `research-fact/v1` lines (K4) | One Facts episode per event: source kind `room`, source ref `<room>#<seq>`, content hash = the event hash | `PurgeSourceAsync` per source ref, then replay; Facts' own `(kind, ref, hash)` idempotency makes a replay of unchanged events a no-op |
| Idea board (K3) | `decision` events from approvals items `knowledge:idea:*` and `knowledge:result:*`; `observation` events of GitHub issue payloads | `KnowledgeApprovals.ApplyAsync`, `GitHubIssueAdapter` through `IdeaStore` | Through the Facts rebuild: ideas are facts in namespace `ideas` |
| Research rounds (K4) | `tool_result`s of a round ingest in a `topic/` room | `RoundIngest` with round `<topic>/round-<n>` | Through the Facts rebuild |
| Hindsight directives | `decision` and `said` events the owner marks as a rule ("a correction becomes a rule") | A directive per event, tagged `room:<key>@<seq>` | UNKNOWN: the Hindsight tool list shows `create_directive` and `list_directives` and no delete; slice 6 starts by checking its API, and a projection that cannot be rebuilt is not added |

Purge reaches projections: `OnPurgedAsync` makes the Facts projection call `PurgeSourceAsync` for the event's source ref, so a purged body leaves no derived fact behind.

Synapse and chronicle are parked (workspace map, 2026-11-01). If either returns, it reads rooms through a projection and keeps no capture path of its own.

### Me rooms, self pages and the session card (slice SM)

Added at the owner's request on 2026-11-01: the room is also where the owner talks to the system, and the system keeps a model of the owner, built from the log like every other projection.

**Streams.** Each personal data source writes into a `me/` room of its own through an adapter, the same envelope and fences as transcripts: body signals (sleep, readiness) to `me/body`, attention (sense readings, screen and phone use) to `me/attention`, conversations to `me/talk` (references only; raw audio stays in its own store), sessions, approvals taps and git activity to `me/work`. The `me` room holds every `correction`, from a session or from the Me screen. Which sources exist on the host is the host's configuration, not this kit's.

**Sharing mode per stream.** Each `me/` room has its own mode. Health, one-time-code, bank and employer streams default to `local-only`; the employer fence applies as everywhere (employer streams never enter).

**Self pages.** A projection rebuilds four pages nightly from the `me/` rooms; every line cites the events it came from (`room:<key>@<seq>`), so a wrong line is traceable and correctable:

| Page | Holds | Built from |
|---|---|---|
| `how-to-talk` | Tone, length, language; topics the owner engages with or skips | `correction` events and the owner's replies |
| `state-now` | Energy, focus, whether an interruption is acceptable | `me/body`, `me/attention` |
| `goals-and-bets` | Open bets and how each is going | `me/work`, the idea board |
| `fields` | What the owner knows well (not to be explained) and is learning | `me/work`, `me/talk` |

The first version seeds each page from the existing Hindsight `personal` bank pages (cited as `hindsight:<page>`), so it does not start empty; seeded lines are replaced as cited events arrive.

**Session card.** `me_card()`, a read-only tool beside `room_brief`: who the owner is in short, the state now, and the rules that apply now (for example: low readiness late in the evening means short answers and no new work), at most 300 tokens (a starting value, set by the check below). Every line carries its citation. It is read at the start of every hand.

**Me screen.** The approvals shell gets a screen listing every stream with its mode; the owner scrubs a stream's history, corrects any page line (which writes a `correction` to `me`), and turns a stream off. The screen is the shell's; this kit gives it the read model and the correction append.

**Every stream needs a reader.** A stream is kept only while a page or a decision cites it. A stream no page line has cited for 30 days (a starting value) is paused: its adapter stops writing, nothing is deleted, and the Me screen shows it as paused with the date of its last citation.

## Check and stop

Measured after S1c, on the owner's own sessions; the gold answers stay private, outside the repository, and the harness reads their path from an argument (as ADR 0005's gold sets do).

**Brief quality.**

- **Sessions.** The 10 most recent finished personal sessions that wrote a `docs/HANDOFF.md`, chosen by that rule before the run, not by hand.
- **Point T.** The transcript line of the tool call that wrote the handoff, so both arms describe the same moment.
- **Questions.** Five per session, the same five every time: (1) what was the goal; (2) what is done, with its evidence; (3) what was tried and failed; (4) which decision was taken, and why; (5) what is the next step, and which side effects are still in force and how each is reversed. The owner writes gold answers from the transcript up to T before either arm runs.
- **Arms.** A: a fresh agent with only the `room_brief` tool, `as_of` capped at T by the harness, any filters. B: a fresh agent with only that session's `HANDOFF.md`. Same model, same prompt.
- **Grading.** The owner grades all 100 answers against gold, blind: arms shuffled and unlabeled.
- **Re-asks.** Three real unfinished tasks are continued in a new session given only the room key. Every question the agent asks the owner is marked by the owner as a re-ask when its answer is in the room up to T.

**Check.** Arm A answers at least 40 of 50 (80%, a starting value to calibrate), and 0 re-asked facts in 3 of 3 continued tasks.

**Latency.** The tailer runs off the tool path, so its cost to a tool call is measured, not assumed: a scripted session of 200 tool calls runs with the tailer on and off, and the difference in p95 tool round trip (`tool_result.timestamp − tool_use.timestamp`) is reported. The cost of ingesting one call (scan plus two appends) is reported too, so a hook variant can be judged before anyone builds it. Same method as `docs/benchmarks/facts-library.md`: warm-up excluded, p95 over at least 200 runs.

**Stop.** Arm A scores below arm B on the same sessions, or ingest adds more than 100 ms p95 per tool call (the on/off difference, or the per-call cost if ingest ever runs inside a hook). Then the transcripts stay as they are, the session viewer stays the only reader of them, and S2 onward are not built; ADR 0007 is amended with the numbers.

**Gate before S4 (not a sixth memory).** Projections only start if S6 is feasible: the session retain job can read rooms instead of transcripts. If it cannot, rooms stay a brief over transcripts and are not called the raw layer.

**Me check (slice SM).** The measure of "understands me" is corrections per 10 sessions: owner turns that reject or restate (a fixed marker list such as "nah", "you missed", "wrong", "I said", plus every `correction` event), counted by the same rule before and after. Baseline: the last 30 personal transcripts before the card ships; the owner audits the baseline's hits once and the list is fixed after that audit. **Check:** over the 30 sessions after the card ships, corrections per 10 sessions fall by half (a starting value). **Stop:** no fall after 30 sessions; then the card is noise and is cut back to the rules already in the owner's instruction file.

## Value hypothesis and cheapest test

**Hypothesis.** A hand that starts from a room brief repeats no work and re-asks nothing, so sessions stay short (82% of re-read tokens in 14 days came from sessions past 300k) and a crashed or stopped run resumes at the right place. For people: the same rooms let anyone (the owner, a reviewer, a later agent) see what happened and what is still reversible, with no handoff ritual.

**Cheapest test, before any S1 code.** A throwaway script applies the brief's fixed rules (goal, decisions, side-effect rules, snapshots, failures, last 100 events) straight to the 10 transcripts, writes each brief to a file, and the brief-quality protocol above runs with that file in place of the tool. If that brief scores below `HANDOFF.md`, nothing is built and this spec is amended. The latency half cannot be tested before the tailer exists; it is the first number S1c reports.

## Open points for Yehor

1. **What is a room in Nytka?** Nytka's docs have no "room" concept (searched 2026-11-01; the hits are Android's Room database and "people in the room" in the audio specs); the nearest are conversations and people. This spec assumes a room is one shared, ordered timeline per topic that several participants write into, and maps a Nytka conversation to `session/`-like rooms with speakers as actors. If Nytka's room is a place or a group of people over time, consumer 3 maps to a `topic/` room per group instead, and the envelope may need a speaker field.
2. **Which service hosts the tools and the table?** Recommended: feed-eater, because its PostgreSQL already holds the Facts namespaces, so the Facts projection writes in the same transaction as its checkpoint and no new container appears (workspace rule D-39). Alternative: chargehand, which is consumer 2 and already an MCP server; it would put the owner's session log into a public orchestrator's database.
